# 스마트 머니 v1.1

카드 명세서와 통장 내역을 **파일로 가져와** 수입·지출, 고정비·변동비, 월간 예산을 한 화면에서 관리하는 한국형 가계부 PWA입니다. AI가 절약할 항목을 짚어 주고, 카드 대금과 명세서를 스스로 이어 맞춥니다.

**서버가 없습니다.** 앱 전체가 휴대폰 안에서 단독으로 돌아갑니다. 가계부는 기기의 SQLite에 저장되고 기기 밖으로 나가지 않으며, 비행기 모드에서도 조회·입력·수정이 모두 됩니다. 한 기기에 **여러 사용자**를 등록할 수 있고 사용자마다 계좌·거래·예산이 완전히 분리됩니다.

---

## v1.1에서 더한 것

v1.0은 **넣고 · 가려내고 · 보는** 것까지였습니다. v1.1은 **사람이 잊는 것**을 앱이 먼저 말하게 했습니다 — 이 가계부의 가장 큰 약점이 계산이 아니라 거기에 있었기 때문입니다.

| 더한 것 | 무엇을 메우나 |
| --- | --- |
| **홈 알림** | 이번 달 명세서가 아직 없는 카드 · 오래된 백업 · 며칠 뒤 나갈 정기 결제 · 지난번보다 오른 금액 · 씀씀이가 늘어난 카테고리. 밀거나 눌러서 닫고, 닫은 것은 `숨긴 N건 보기`로 되돌립니다 |
| **백업 리마인더** | 서버가 없어 기기 고장이 곧 전손입니다. 간격은 `설정 → 기타 설정`에서 정하고 `0일`이면 끕니다 |
| **한 장 리포트** | 한 달·한 해를 한 장으로 — 수입·지출·고정/변동/저축·상위 카테고리·견준 기간과의 차이. 인쇄 대화상자의 `PDF로 저장`이 곧 저장입니다 |
| **환불·취소 짝짓기** | 되돌아온 돈을 원래 결제와 짝지어 보여 줍니다. 두 줄 다 명세서에 있는 줄이라 **지우지 않습니다** |

## 빠른 시작

```bash
npm ci
npm run dev      # http://localhost:3000 — 포트를 바꾸지 마세요 (아래 설명)
npm run check    # 타입 검사 + eslint + 회귀 세트 16종
npm run build    # dist/
```

처음 열면 사용자가 0명이므로 **등록 화면**이 먼저 나옵니다. 이름·연락처 → PIN 6자리를 거치면 홈에 **네 걸음 안내**(카드·계좌 등록 → 명세서 가져오기 → 고정비 가려내기 → 예산 정하기)가 뜹니다.

> **`npm run dev`의 포트 3000을 바꾸지 마세요.** 모든 데이터가 IndexedDB에 있고 브라우저는 저장소를 **출처(origin)별로** 나눕니다. 포트가 출처의 일부라 `:5173`으로 뜨면 **빈 가계부**가 열리고, 사용자가 0명이니 규칙대로 첫 등록 화면이 나옵니다 — 아무것도 지워지지 않았는데 전부 사라진 것처럼 보입니다. 실제로 겪은 사고라 `strictPort: true`로 막아 두었습니다.

## 데이터는 어디에

```
휴대폰
 └── 브라우저 / 설치된 PWA
      ├── sql.js (WASM SQLite 엔진)
      ├── IndexedDB   ← finance.db 바이트가 통째로
      └── localStorage ← AI 키 · 기억한 명세서 형식 · 화면 취향
```

- **DB 파일은 배포되지 않습니다.** 최초 실행 때 기기에서 만들어지고, 그 뒤로는 앱만 교체됩니다. 새 버전을 올려도 가계부는 그대로입니다.
- 테이블은 12개(`users` · `accounts` · `transactions` · `budgets` · `budget_configs` · `budget_policy` · `category_rules` · `custom_categories` · `categories` · `ai_analyses` · `sms_inbox` · `undo_log`), 스키마 버전 **v18**.
- 구조를 바꿀 때는 `src/db/schema.ts`의 `MIGRATIONS` 끝에 항목을 **덧붙이고** `SCHEMA_VERSION`을 올립니다. **이미 배포된 마이그레이션은 고치지 않습니다** — 어느 버전에 머물러 있던 기기든 같은 결과에 닿아야 합니다.
- 버전만 올라가고 컬럼이 없는 기기가 실제로 발생한 적이 있어, 매 실행마다 모양을 확인하고 없으면 되살립니다(`EXPECTED_COLUMNS` · `EXPECTED_TABLES`).

**백업**은 `.db` 파일 전체이고 암호를 걸 수 있습니다(PBKDF2 600,000회 + AES-256-GCM, 확장자 `.smbk`). 암호를 잊으면 **누구도 열 수 없습니다** — 서버가 없어 되돌릴 방법이 없습니다.

## 접속

배포된 앱은 Cloudflare Workers의 정적 자산으로 서비스됩니다. 주소는 이 형태입니다.

```
https://smart-money.<계정 서브도메인>.workers.dev
```

`smart-money`는 [`wrangler.jsonc`](wrangler.jsonc)의 `name`이고, 뒤쪽은 Cloudflare 계정마다 다릅니다. **내 주소를 확인하는 곳**:

- Cloudflare 대시보드 → **Workers & Pages** → `smart-money` → **Settings → Domains & Routes**
- 또는 로컬에서 `npx wrangler deploy`를 돌리면 마지막 줄에 찍힙니다.

휴대폰에서는 그 주소를 열고 브라우저 메뉴의 `홈 화면에 추가`/`앱 설치`를 누르면 전용 앱처럼 씁니다. 앱 안의 `설정 → '스마트 머니' 전용 앱 설치`에 QR과 기종별 안내가 있습니다.

> **주소가 다르면 데이터도 다릅니다.** 가계부는 IndexedDB에 있고 브라우저는 저장소를 **출처(origin)별로** 나눕니다 — 개발 서버(`localhost:3000`)와 배포본은 서로의 데이터를 볼 수 없고, 도메인을 바꾸면 따라오지 않습니다. 옮기려면 백업·복원을 거쳐야 합니다.

## 배포 설정

한 번만 해 두면 그다음부터는 **`main`에 푸시하는 것이 곧 배포**입니다.

### 1. GitHub

```bash
git init
git add -A
git commit -m "first"
git branch -M main
git remote add origin https://github.com/<계정>/<저장소>.git
git push -u origin main
```

**저장소를 공개로 둘 생각이면 `.gitignore`부터 확인하세요.** 가계부 백업(`.db`·`.smbk`)이 공개 저장소에 올라간 일이 실제로 있었습니다. 지금은 이름이 아니라 **모양으로** 거릅니다.

```
finance.db · DB Backup/ · *.db · *.sqlite · *.smbk   ← 실제 가계부
*.docx · *.pptx · *.xlsx                              ← 보고서·명세서 샘플
```

푸시하면 [`.github/workflows/check.yml`](.github/workflows/check.yml)이 `npm ci` → `npm run check` → `npm run build`를 돌립니다. "커밋 전에 검사한다"는 규칙은 사람이 기억해야 하고 언젠가 잊히기 때문입니다.

### 2. Cloudflare

Cloudflare 대시보드 → **Workers & Pages** → **Create** → **Import a repository** → 위 저장소 선택.

| 항목 | 값 |
| --- | --- |
| Build command | `npm run build` |
| Deploy command | `npx wrangler deploy` |
| Build output directory | **비워 둡니다** |
| 환경 변수 | `NODE_VERSION` = `22` |

- **출력 디렉터리를 대시보드에 적지 않습니다.** [`wrangler.jsonc`](wrangler.jsonc)의 `assets.directory`가 그것을 정합니다 — 두 곳에 적으면 한쪽만 고쳐집니다.
- `not_found_handling: "single-page-application"`이 없으면 **새로고침할 때 404**가 납니다. React 진입점이 하나뿐이라, 못 찾은 경로에는 `index.html`을 줘야 합니다.
- `NODE_VERSION`을 20.19 미만으로 두면 `@vitejs/plugin-react`가 경고를 냅니다. 빌드는 되지만 22로 고정해 두는 편이 안전합니다.
- `wrangler.jsonc`의 `name`은 대시보드의 프로젝트 이름과 **같아야** 합니다. 그 값이 곧 `*.workers.dev` 서브도메인입니다.

푸시 후 1~3분이면 배포됩니다.

### 3. 배포가 반영됐는지 확인하는 법

**PWA는 한 번 실행에서 새 버전을 받고 다음 실행에서 보여 줍니다**(`registerType: 'autoUpdate'`). 그래서 고친 것이 안 보여도 실패가 아닐 때가 많습니다 — **두 번 여세요.**

빌드 시각이 번들에 박혀 있어(`__BUILD_TIME__`) **`카드·계좌` 탭의 DB 카드**에 표시됩니다. 그 시각이 곧 "지금 이 기기가 돌리는 버전"입니다.

### 4. 무엇이 웹에 올라가는가

**`dist/`뿐입니다.** `vite build`가 만든 번들과 `public/`을 그대로 복사한 것이 전부이고, 저장소 루트의 다른 파일은 서비스되지 않습니다.

**`public/`에 둔 것은 그대로 공개됩니다** — 주소만 알면 누구나 내려받습니다. 가계부 백업·명세서 샘플·메모를 그 안에 두지 마세요. `.gitignore`는 로컬에서 `npx wrangler deploy`를 직접 할 때는 이 경로를 막아 주지 않습니다.

## 기술 스택

React 19 · TypeScript 5 · Vite 6 · Tailwind CSS 4 · Recharts · lucide-react · vite-plugin-pwa · sql.js(WASM SQLite) · SheetJS · `@google/genai` · `@anthropic-ai/sdk`

빌드 결과물은 정적 파일(HTML/JS/CSS/WASM)뿐이고 실행에 백엔드가 필요하지 않습니다 — 그래서 배포가 `dist/`를 그대로 올리는 일로 끝납니다(위 [배포 설정](#배포-설정)).

첫 로드는 **773KB(gzip 214KB)**이고, 차트·엑셀 리더·AI SDK·카드계좌 화면·가져오기 창은 **필요할 때** 내려받습니다.

## AI는 선택입니다

`설정 → AI 등록`에서 **내 API 키**를 넣으면 Gemini·Claude·ChatGPT 중 하나로 동작합니다. 키는 기기의 localStorage에만 있고 사용자별로 분리됩니다.

- **키가 없어도 앱의 모든 기본 기능이 동작합니다.** AI는 거들 뿐입니다.
- **결제 문자 파싱은 일부러 규칙 기반**입니다 — 문자에 든 가맹점·금액·잔액을 외부로 보낼 이유가 없고, 규칙이면 키 없이 즉시 끝납니다.
- 명세서 열 인식에 AI를 쓸 때도 **머리글과 표본 5행만** 보냅니다. 파일 전체를 보내지 않습니다.

## 손대기 전에 알아둘 것

전체는 [CLAUDE.md §14 함정](CLAUDE.md)에 있습니다. 가장 자주 물리는 것만:

- **`vite.config.ts`의 `globPatterns`에서 `wasm`을 빼지 마세요.** 기본 패턴에 없습니다. 빠지면 오프라인에서 SQLite 엔진이 캐시되지 않아 **화면은 뜨는데 로딩에서 멈춥니다.**
- **모달은 `createPortal`로 `<body>`에 올리세요.** 기기 프레임이 쌓임 맥락을 만들어 내부 z-index로는 빠져나올 수 없습니다. Escape는 맨 위 창만 닫아야 합니다.
- **훅은 조기 반환보다 위에.** `if (!isOpen) return null` 아래에 훅을 더하면 앱 전체가 흰 화면이 됩니다.
- **금액은 `utils/format.ts`를 거칩니다.** `parseInt("1,234,000")`은 1입니다.
- **하드코딩한 예시값을 폴백으로 쓰지 마세요.** 목 데이터를 걷어낸 뒤, 거래가 0건인 기기에 "재무 건강도 78점"과 등록한 적 없는 구독 이름이 사실처럼 떠 있었습니다. 모르면 `–`로 둡니다.
- **SheetJS는 npm 배포판 대신 CDN 타르볼**을 씁니다(`package.json`의 `xlsx`가 URL인 이유).

## 보안 한계 (정직하게)

인증은 **한 기기를 신뢰하는 사람끼리 나눠 쓰는 수준**입니다.

- 6자리 PIN은 조합이 100만 가지입니다. PBKDF2 310,000회가 한 번의 시도 비용을 올릴 뿐, 기기를 확보한 사람이 시간을 들이면 전수 조사가 가능합니다. 시도 횟수 제한이 없습니다.
- **기기 안의 가계부는 암호화되지 않습니다.** 브라우저 저장소를 직접 열면 PIN 없이도 읽힙니다. AI 키도 localStorage에 평문입니다.
- 사용자 간 분리는 **앱 안에서만** 유효합니다. 같은 DB 파일에 함께 들어 있습니다.
- **백업 암호화는 파일 하나만 지킵니다** — 기기를 떠나는 유일한 물건이기 때문입니다.
- 세션·토큰 개념이 없습니다.

분실 위험이 있는 기기나 서로를 신뢰하지 않는 사용자끼리 쓰려면, PIN에서 키를 유도해 사용자별로 데이터를 암호화하는 작업이 추가로 필요합니다.
