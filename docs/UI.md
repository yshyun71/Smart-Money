# 화면 — 구성·표시 규칙·PWA

> **12 · 13절.** [CLAUDE.md](../CLAUDE.md) 묶음의 일부입니다. 절 번호는 소스 주석이 가리키는 값이라 바뀌지 않습니다.

화면은 판정을 하지 않습니다(§17.5). 여기 적힌 것은 **무엇을 어느 자리에 두는가**와 **같은 일은 같은 모양으로 보여야 한다**는 규칙입니다.

## 12. 화면 구성

하단 탭: `홈` · `소비분석` · `예산·알림` · `AI절약` · `카드·계좌`.

**상단 월 이동 바는 `카드·계좌`와 `소비분석` 탭에서 감춥니다**(`MobileHeader`의 `MONTHLESS_TABS`). **이유가 두 가지이고 서로 다릅니다** — 자세한 것은 §12.5.

- `카드·계좌` — 달이라는 개념이 없습니다. **지금의** 잔액과 **앞으로** 낼 청구액을 보여 주므로 달을 고를 여지가 없고, `selectedMonth`를 읽는 곳이 한 군데도 없습니다. 눌러도 아무 일이 없는 조작기는 사용자가 자기 잘못을 찾게 만듭니다 — "이게 하는 역할이 무엇인가요?"라는 질문을 받았습니다.
- `소비분석` — 달에 따라 값이 **바뀌는데도** 감춥니다. 그 화면이 **자기 기간 선택기를 갖기** 때문입니다.

→ 새 탭을 넣을 때 "달을 쓰니까 목록에서 빼야지"로 판단하지 마세요. 기준은 **그 화면이 자기 기간 선택기를 갖는가**입니다. **포함이 아니라 제외 목록**인 이유: 나머지 탭은 전부 달에 따라 값이 바뀌고 자기 선택기가 없으므로(컨텍스트의 `transactions`가 이미 그 달로 걸러진 목록), 새 탭에서 바를 잃는 쪽보다 필요 없을 때 빼는 쪽이 안전합니다.

### 12.1 계좌 내역 화면의 조건 블록 순서

```
[헤더: 아이콘 · 이름 · 기관·번호 · 연필(정보 수정) · 닫기]
[버튼 3개: 엑셀·CSV · 직접 추가 · 카테고리 관리]
[AI 자동 분류 + 돋보기(설명 펼침)]
┌ 조회 조건 ──────────────────────────
│ (카드만) 결제월 기준 / 이용일자 기준
│ 월별 / 기간별
│   월별: 2026년 08월  ◀  2026년 09월 ▾  ▶  2026년 10월
│   기간별: [YYYY-MM] 부터 [YYYY-MM] 까지
│ 전체
│ (계좌만) 지출전체 / 고정지출 / 변동지출
│ (계좌만) 수입전체 / 고정수입 / 변동수입
│ (카드) 전체 / 고정지출 / 변동지출
│ (카드만) 전체 / 카드대출 / 일시불 / 할부
│ 카테고리 드롭다운
│ ─────────────
│ 지출전체 11건                        3,698,536원
│ ███████████▓▓▓▓░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░
│ ● 고정 8건 · 241만  ● 변동 3건 · 129만
│ 수입전체 3건                         4,530,000원
│ ████████████████████████████████████████████
│ ● 고정 1건 · 450만  ● 변동 2건 · 3만
│ ☑ 전체 선택                             선택 삭제
│ 선택 3건 합계                            1,234,000원
└──────────────────────────────────
[월별로 묶인 목록]
```

- **머리에 잔액을 두지 않습니다.** 이 화면은 **그 달의 수입·지출**을 보는 자리인데, 잔액은 달을 따르지 않고 자기 기준일시를 갖습니다(§8). `2026년 6월`을 보면서 `기준 2026년 09월 14일`이 나란히 있으면 홈 화면에서 겪은 것과 같은 오해가 생깁니다(§12.7 — "기준월을 바꿔도 안 변한다"). 잔액을 보고 고치는 자리는 **`카드·계좌` 목록**이고, 같은 `BalanceEditModal` 을 씁니다.
- **고른 조건이 몇 건이고 얼마인지는 조건 블록 안에서 그림으로 말합니다** — 막대 둘, 각각 고정과 변동(§6.6). **선택과 무관한 값**이고, 그 아래 `선택 N건 합계`가 골라 둔 것의 값입니다. 둘은 다른 질문에 답합니다.
  → **여섯 개를 여섯 막대로 그리지 않습니다.** `지출전체 = 고정지출 + 변동지출` 이라 여섯을 나란히 세우면 **같은 돈이 두 번** 그려져 없는 돈이 있는 것처럼 보입니다. 막대는 둘, 조각이 둘씩입니다.
  → **두 막대를 한 기준으로 잽니다**(`barScale` — 둘 중 큰 쪽). 각자 100%로 잡으면 300만원 수입과 100만원 지출이 같은 길이가 되어, 가장 먼저 읽혀야 할 사실이 사라집니다.
  → **차트 라이브러리를 쓰지 않습니다.** 이 창은 지연 로드가 아니라 주 청크에 있어서 `recharts` 를 끌어오면 첫 로드에 **468KB**(gzip 132KB)가 붙습니다(§13.3). 비율 막대는 `div` 두 개면 됩니다 — 실제로 +6KB 로 끝났습니다.
  → **막대가 말하는 범위는 기간과 카테고리까지**입니다. 정기성은 빼고 셉니다 — 이 그림은 "지금 무엇을 보고 있나"가 아니라 "이 달이 어떤 모양인가"이고, 보고 있는 조각은 **밝게** 표시해 알려 줍니다. 그것까지 걸러 내면 `고정지출`을 고른 순간 막대가 한 조각만 남아 견줄 것이 없어집니다.
  → **조각을 누르면 그 조건으로 걸러집니다.** 보이는 것을 그대로 가리키는 편이 칩을 찾아 누르는 것보다 짧습니다. **칩도 그대로 둡니다** — 막대는 0원인 조각을 그리지 않으므로 그 자리로 가는 길이 하나는 있어야 합니다.
  → **건수를 함께 적습니다.** 금액만으로는 "한 건이 큰 것"과 "작은 것이 여러 건 쌓인 것"이 같아 보이고, 줄일 곳을 찾는 사람에게는 전혀 다른 이야기입니다.
  → 이름은 **누른 칩의 글자 그대로**입니다(`kindLabel` 이 `kindGroups` 에서 꺼내 옵니다). 따로 적어 두면 칩을 고칠 때 한쪽만 바뀝니다.
  → 카드는 막대가 **하나**이고(수입이 없습니다), 차감·환불이 있으면 `− 금액`을 아래에 따로 적습니다 — 그것은 수입이 아니라 청구액을 줄이는 것입니다(§9.5).
  → 예전에는 이 값이 **화면 맨 위** `지출 합계`·`수입 합계` 였습니다. 값은 그때도 필터를 따랐는데 자리가 조건 블록에서 멀어, 눌러도 바뀌는 줄 몰랐습니다 — "선택을 해야 합계가 보인다"는 신고가 그래서 나왔습니다. **답이 있어도 묻는 자리에 없으면 없는 것입니다.**
  → **기본을 전체 선택으로 두지 않습니다.** 선택은 `선택 삭제`와 `AI 자동 분류`의 대상이라, 처음부터 전부 골라져 있으면 오조작 한 번이 그 달을 통째로 지웁니다.

- **선택은 지금 보고 있는 것에 대한 것입니다.** 조회 조건이 하나라도 바뀌면(달·기간·방향·정기성·결제 방식·카테고리) **선택이 비워집니다.**
  → 예전에는 id 집합이 그대로 남았습니다. 그런데 이 화면의 모든 행동은 **보이는 줄만** 대상으로 합니다 — `선택 N건`·`선택 합계`·`선택 삭제`·`AI 자동 분류` 가 전부 `entries.filter(...)` 를 지납니다. 그래서 안 보이는 id 는 아무 일도 하지 못하면서 **필터를 넓힐 때만 체크된 채 되살아났습니다.**
  → 게다가 `전체 선택` 은 집합을 **갈아엎습니다.** 그래서 `변동지출`에서 고른 것이 `고정지출`에서 전체 선택을 누른 순간 사라지고, `지출전체`로 넓히면 고정만 체크된 채 보였습니다 — 한 화면이 세 가지 규칙을 섞어 쓰고 있었던 셈입니다(사용자 신고).
  → 비우는 쪽을 고른 까닭: **"보이는 것이 고른 것의 범위"** 한 문장으로 설명이 끝나고, `선택 0건` 이라고 적혀 있는데 앱이 12개를 들고 있는 상태가 없어집니다(§17.1).
  → **AI 분류 뒤의 재시도 선택은 살아남습니다.** 분류는 조회 조건을 건드리지 않으므로 실패한 건이 그대로 골라진 채 남습니다.

### 12.2 표시 규칙

- **연락처는 `utils/format.ts`의 `formatPhone`으로 끊어 보입니다.** 숫자만 눌러도 `010-1234-5678`이 되고, 입력 중에도 자릿수에 맞춰 자랍니다. `010`은 11자리로 정해져 있어 가운데가 처음부터 4자리이고, 서울(`02`)만 앞자리가 둘입니다. **직접 만들어 쓰지 마세요** — 같은 함수가 화면마다 복사돼 세 벌이 돌아다닌 적이 있습니다.
  → 자릿수 검사와 "바뀌었는가" 판정은 **숫자만** 견줍니다. 하이픈 없이 저장된 옛 값이 화면에서는 하이픈이 붙어 보이므로, 글자로 비교하면 손대지 않아도 바뀐 것으로 잡힙니다.
- **제목 줄 + 버튼은 버튼이 먼저 폭을 잡습니다.** `flex justify-between` 안에서 둘 다 줄어들 수 있게 두면 **버튼 글자가 두 글자씩 갈립니다** — `새로고침`이 두 줄, `7월 실제 내역으로 채우기`가 두 줄이 된 적이 있습니다. 버튼에 `shrink-0 whitespace-nowrap`, 글 묶음에 `min-w-0`을 주세요. 접혀도 읽히는 쪽은 설명 문구이고, 버튼 글자와 금액은 접을 곳이 없는 말입니다.
- **모든 금액에 3자리 콤마**를 씁니다. `utils/format.ts`의 `won`/`withCommas`를 쓰세요. 입력 필드는 `formatAmountInput`/`parseAmountInput` 쌍으로 다룹니다. **`parseInt("1,234,000")`은 1입니다** — 직접 파싱하지 마세요.
- 계좌는 **인디고**, 카드는 **앰버**입니다(`utils/accountTone.ts`). 등록 버튼·요약 카드·목록 아이콘·상세 화면 헤더가 모두 같은 색을 씁니다.
- 데이터가 없으면 **숫자를 지어내지 않습니다.** 분석 전 건강도는 `–`와 `아직 분석 전`으로 표시합니다. 예시 가맹점명을 실제 데이터처럼 보여주지 마세요.

### 12.3 카테고리 순위표는 접어 둡니다

`소비분석`의 `카테고리별 지출 순위 & 비중`은 위의 도넛 범례와 **같은 숫자를 다시 말합니다.** 둘 다 펼쳐 두면 화면의 절반이 같은 내용인데, 스크롤을 내리는 사람에게는 아래쪽이 새 정보처럼 보입니다. 그래서 제목 줄 전체가 토글이고 `카테고리 전체 보기` / `접기`로 여닫습니다(기본은 접힘). 순위·비중 막대는 "전부 훑어볼 때" 쓰는 것이니 그때 펼치면 됩니다.

### 12.4 기간 추이 (`services/trend.ts` · `PeriodTrendPanel`)

`소비분석`의 세 번째 탭입니다. 월별 분석은 한 달, 연도별 비교는 한 해를 보는데 **그 사이의 질문**에 답할 자리가 없었습니다 — "작년 3월부터 올해 2월까지 식비가 어떻게 움직였나".

```
기간 [YYYY-MM] 부터 [YYYY-MM] 까지   (최근 3·6·12개월 바로 고르기)
구분 전체 / 수입 / 지출
카테고리 전체 / (그 기간에 있는 것만, 금액 큰 순)
```

- **기간 추이는 아래의 월·연도 분석을 대신합니다**(같은 화면에 겹쳐 놓으면 어느 숫자가 어느 기간의 것인지 알 수 없습니다). 나머지 모드의 본문은 손대지 않았습니다.
- **내역이 없는 달도 0으로 남깁니다.** 빈 달을 빼면 선이 이어져 "그 달에 쓰지 않았다"가 "그 달이 없었다"로 보입니다. 월평균도 빈 달을 한 달로 셉니다 — 그래야 월평균입니다.
- **카테고리 목록에는 그 기간·그 구분에 실제로 있는 것만** 올립니다(`categoriesInRange`, 금액·건수 함께). 전체 목록을 넣으면 고르는 대로 빈 차트가 나옵니다. 구분을 바꿔 고른 카테고리가 사라지면 `전체`로 되돌립니다.
- 차트: `전체`는 수입·지출 막대에 순액 선을 겹치고(0선 표시), 한쪽만 고르면 막대 + **월평균 점선**입니다. 어느 달이 평균을 넘었는지가 추이에서 가장 먼저 궁금해지는 것이라, 평균보다 큰 달은 진한 색으로 칠합니다.
- **증감은 구분에 따라 색이 반대입니다.** 지출이 늘면 붉은색, 수입이 늘면 초록색 — 같은 "증가"가 서로 다른 뜻입니다.
- **첫 달이 0이면 증감률을 보여 주지 않습니다.** 0으로 나눈 값을 `∞`나 큰 수로 적는 대신 변화량만 말합니다(§17.1).
- 막대나 달별 목록을 누르면 그 달 그 카테고리의 내역이 열립니다(§11.7) — `구분`과 `카테고리`를 모두 고른 상태에서만입니다. `전체`에서는 무엇을 열어야 할지 정해지지 않습니다.
- 구간이 120개월을 넘으면 잘라 냅니다. 그보다 길면 축이 읽히지 않습니다.

### 12.8 되돌리기 어려운 일은 한 창으로 묻습니다

`ConfirmModal` 하나가 확인 전부를 맡습니다. 예전에는 **`window.confirm` 이 열 곳**이었습니다.

- OS 대화창이 앱의 모달과 전혀 다르게 뜨고, **설치된 PWA 에서는 주소(origin)까지 노출**됩니다.
- 무엇이 함께 사라지는지 **한 문장에 밀어 넣을 수밖에** 없었습니다. 이 창은 **항목으로** 보여 줍니다 — 사용자 삭제(§5)가 이미 그렇게 하고 있었습니다.
- **되돌릴 수 있으면 그 사실을 말합니다**(`undoable`) — `설정 → 기타 설정에서 되돌릴 수 있습니다`. 아니면 `이 작업은 되돌릴 수 없습니다`. 같은 버튼이라도 결정의 무게가 달라집니다.
- z-10002 입니다(§14.4의 가장 위). 다른 창 위에서 뜨므로 아래 창의 Escape 핸들러에 **이 창의 열림 상태를 조건으로** 넣으세요.

### 12.5 기간 선택은 한 자리에

`소비분석`의 세 모드가 **기간을 같은 자리에서** 고릅니다 — 모드 탭 바로 아래.

```
[월별 (9월)]  [연도별 비교]  [기간 추이]
────────────────────────────────────────
월별      분석 기준 월   ‹  📅 2026년 9월 104건  ›
연도별    분석 기준 연도  2025년 · 2026년 · 2027년
기간 추이  [2026-04] 부터 [2026-09] 까지 · 최근 3·6·12개월
```

예전에는 **월별만** 조작기가 화면 밖 위쪽(상단 월 이동 바)에 있었습니다. 셋 중 하나만 규칙이 다르고, 나머지 두 모드에서는 그 바가 **아무 일도 하지 않았습니다.**

- **모드에 따라 바를 여닫지 않고, 탭 전체에서 감춥니다.** 모드별로 하려면 뷰 안쪽 상태(`timeframeMode`)를 헤더가 알아야 해서 `App`이나 컨텍스트에 UI 플래그를 두게 되는데, 화면 하나의 사정을 앱 구조에 새기는 일입니다. 게다가 바가 나타나고 사라지면 레이아웃이 튑니다. 탭 전체에서 감추면 배관이 **한 줄도** 필요 없습니다.
- 고른 달은 전역 `selectedMonth`에 그대로 씁니다. 상단 바로 바꾸던 것과 **똑같이 동작**하고 예산·홈·AI절약도 같은 달을 따릅니다.
- **`연도별 비교`의 기준 연도는 "고른 값"과 "보여 줄 값"을 나눕니다.** 고르지 않은 상태는 `null` 이고, 실제로 보여 줄 해(`activeYear`)는 `고른 해(자료에 있을 때) → 보고 있는 달의 해 → 가장 최근 해` 순으로 **데이터에서** 정합니다. 칩·제목·집계가 모두 그 하나를 봅니다.
  → 예전에는 `"2026년 (예상 누적)"` 이라는 **데이터에 없는 문자열**이 초기값이었습니다. 집계의 `year` 는 `"2026"` 이라 어느 칩도 선택으로 보이지 않았고, 제목에는 그 문구가 그대로 새어 나왔습니다 — 2026년 자료를 보여 주면서 무엇을 보고 있는지만 말하지 못한 상태였습니다. **없는 값을 기본값으로 적어 두지 마세요**(§17.1).
  → 막대그래프 제목의 `"2025 vs 2026"` 도 코드에 박혀 있었습니다. 해가 바뀌거나 2024년 자료를 가져오면 거짓이 되므로, 있는 해로 만듭니다.
- 가운데를 누르면 **계좌 내역과 같은 `MonthPickerModal`**이 열립니다(연월 직접 선택 + 월별 건수). 새로 만들지 않았습니다.
- 달 이름 옆에 그 달 **건수**를 적습니다 — 빈 달을 헛되게 열지 않게 됩니다.
- `기간 추이` 패널은 모드를 떠나면 언마운트되므로, 다시 들어올 때 **그때의 `selectedMonth` 기준 최근 6개월**로 시작합니다. 월별에서 달을 옮긴 뒤 기간 추이로 가면 그 달이 끝점이 되어 자연스럽게 이어집니다(§14.7의 함정을 피하는 쪽입니다 — 낡은 구간을 들고 있는 것보다 낫습니다).

### 12.6 연월을 고르는 자리는 모두 같은 창

**`MonthPickerModal` 하나가 연월 선택 전부를 맡습니다.** 자리마다 다른 방식을 두면 같은 일을 하는 조작기가 화면마다 달라 보이고, `type="month"` 는 기기·브라우저마다 다른 모양이 뜹니다.

| 자리 | 무엇을 고르나 |
| --- | --- |
| 상단 월 이동 바 | 기준 월 (`selectedMonth`) |
| 계좌 내역 · 월별 | 조회 월 |
| 계좌 내역 · 기간별 | 시작 월 · 끝 월 |
| 소비분석 · 월별 (§12.5) | 분석 기준 월 |
| 기간 추이 (§12.4) | 시작 월 · 끝 월 |
| 가져오기 | 결제(청구) 년월 |

- **달 이름 자체가 버튼이고 옆에 `⌄` 가 붙습니다.** 화살표만 있을 때는 지난 봄 명세서를 보려면 아홉 번을 눌러야 했고, 달 이름이 눌릴 것처럼 생겼는데 아무 일도 일어나지 않았습니다 — 가장 눌러 보고 싶은 자리입니다.
- **달마다 건수를 함께 보여 줍니다.** 빈 달을 헛되게 열지 않게 되고, 상단 바는 가계부 전체를, 계좌 내역은 그 계좌를, 가져오기는 **그 카드에 이미 등록된 결제월**을 셉니다("지난달 명세서를 넣었던가"에 그 자리에서 답합니다).
- **건수가 0인 달도 고를 수 있습니다.** 아직 아무것도 없는 달을 골라 그 달로 가져오는 일이 정상입니다 — 흐리게만 보여 주고 막지 않습니다.
- **기간의 양끝은 `min`/`max` 로 서로를 넘지 못합니다.** 시작이 끝보다 뒤면 조회 결과가 조용히 0건이 되므로 애초에 누를 수 없게 합니다. 한 화면에 창을 여러 개 두지 않고 **무엇을 고르는 중인지만 기억**합니다(`monthPicker: "MONTH" | "FROM" | "TO" | null`).
- 창은 z-10000 입니다(§14.4). 아래 모달(계좌 내역 9998 · 가져오기 9999)의 Escape 핸들러에 **그 창이 열려 있는지 조건을 넣으세요** — 한 번 누르면 아래 것이 먼저 닫히던 함정입니다.

### 12.7 홈 화면

**기준이 섞이지 않게 순서로 가릅니다.**

```
[무관]   앱 설치 배너 · 첫 사용 안내
[지금]   챙길 것 — 백업 · 명세서 · 오른 금액 · 예고 (12.12)
[8월]    결산 카드 · 예산 경고 · 바로가기(접힘) · 변동비 소진 ·
         고정비 vs 변동비 · AI 절약 하이라이트 · 8월 내역 한 줄
──── 지금 기준 · 기준월과 무관 ────
[지금]   연동된 계좌 및 카드
```

**챙길 것이 맨 위에 있는 이유는 하나뿐입니다: 놓치면 되돌릴 수 없습니다.** 백업 없이 기기를 잃으면 끝이고, 명세서를 빠뜨리면 그 달이 통째로 빕니다. 기준이 섞이는 문제는 그 줄들이 **저마다 자기 달을 이름으로 말해**(`9월 명세서가 아직 없습니다`) 생기지 않습니다 — 바로가기 여섯 개를 기준월 구역에 그냥 둔 것과 같은 근거입니다(숫자를 말하지 않는 것은 기준월과 모순될 수 없습니다).

예전에는 자산 요약이 **가운데에 끼어** 기준이 다섯 번 바뀌었습니다 — "화면의 일관성이 없다"는 신고를 받았습니다. 전환을 **한 번**으로 줄이고 그 자리에 구분선이 이름을 답니다. 구분선을 **기준월 바에서 멀리** 두는 것도 일부러입니다: 바로 밑에 놓으면 `2026년 8월`에서 눈을 떼는 순간 안 바뀌는 숫자를 만나 같은 오해가 되살아납니다.

- **제목이 고른 달을 따라갑니다.** `이번 달 가계부 결산`은 7월을 보고 있을 때 **틀린 말**입니다. `2026년 9월 가계부 결산` · `9월 잔여 / 저축 가능액`으로 적고, 이번 달이 아니면 `지난 달`·`다음 달` 배지를 답니다. 변동비 소진 현황의 `9월`은 **코드에 박혀** 있었습니다 — 어느 달을 보든 9월이라고 적혀 있었습니다.
- **재무 점수는 그 달의 AI 분석 결과**(`ai_analyses` PK(user_id, month))입니다. 분석을 돌린 달에만 있으므로 예전에는 배지가 아예 사라졌고, **최근 달에서만 보이는 이유를 알 방법이 없었습니다.** 숫자를 지어내지 않되 **자리는 지킵니다**(§12.2) — 없으면 `N월 분석 전`, 낡았으면 `48점 · 갱신 필요`(§11.6), 누르면 AI절약 탭으로 갑니다.
- **네 금액(총 수입·총 지출·고정비·변동비)을 누르면 그 속이 열립니다** — 카테고리 금액과 같은 길입니다(§11.7). 목록은 **읽기 전용**이고(이 금액들은 적는 값이 아니라 실적입니다), 줄을 누르면 그 거래를 고치러 갑니다. `고정비 + 변동비 + 저축 = 총 지출`이 건수까지 맞습니다(실제 데이터로 검산).
- **자산 요약**(`연동된 계좌 및 카드`)은 계좌마다 한 칸입니다 — 기관명 · 색 점(계좌 인디고 / 카드 앰버, §12.2) · 이름 · 금액.
  → **이 블록만 기준월을 따르지 않습니다.** 잔액은 지금 통장에 있는 돈이고 그 자체로 기준일시를 가지며(§8), 카드 금액은 지금 낼 돈입니다(§9.4의 `pendingBill` — 어느 달을 보고 있는지와 무관). 8월로 옮겨도 숫자가 그대로인 것이 맞습니다.
  → 그래서 **화면이 그렇게 말합니다**: `지금 잔액과 낼 카드대금 — 8월 기준이 아닙니다`. 말하지 않으면 **고장처럼 보입니다** — 실제로 "기준월을 변경해도 내역이 변경되지 않습니다"라는 신고를 받았습니다. `카드·계좌` 탭은 아예 월 이동 바를 감춰 같은 혼동을 없앴지만(§12), 홈에는 그 바가 있어야 하므로 블록이 스스로 밝힙니다.
  → **달에 맞춰 숫자를 바꾸지는 않습니다.** 그 달의 청구액·입출금 합계는 이미 위의 결산 카드가 말하고(§12.7 첫 항목), 과거 시점의 잔액은 기록이 완전하지 않으면 지어내는 것이 됩니다(§17.1).
  → **카드 금액은 `describeBill` 로 계산합니다**(§9.4). 저장된 칸을 읽어 `0원 청구예정`이라고 적던 자리이고, 그것이 카드·계좌 화면과 **다른 말**을 하게 만들었습니다.
  → **계좌는 잔액 아래에 기준일시를 적습니다**(§8). 금액만으로는 뜻이 반쪽이고, 언제 기준인지가 있어야 그 숫자를 믿을 수 있습니다. 기준일시가 없으면 `기준일시 없음`이라고 말합니다(지어내지 않습니다).
  → **칸을 누르면 그 계좌·카드의 내역이 열립니다.** 예전에는 어느 칸을 눌러도 `카드·계좌` 탭만 열려, 거기서 다시 같은 카드를 찾아야 했습니다. 내역 창(`AccountLedgerModal`)은 이제 **`App` 이 뿌리에서 들고 있어** 두 화면이 같은 창을 쓰고, 그 안의 `직접 추가`·`엑셀·CSV`까지 같은 길로 이어집니다 — 누를 수는 있는데 아무 일도 없는 버튼을 남기지 않으려면 함께 이어 두어야 합니다.
- **최근 4건 목록은 한 줄 링크로 바꿨습니다**(`8월 입출금 & 카드 내역 · 101건`). 홈에서 값이 가장 낮은 블록이었습니다 — 맛보기 4건이고 전체 내역은 한 번만 누르면 되며, 제목이 `최근`인데 실제로는 **그 달 안에서의 최근**이라 기준을 흐렸습니다. 250px 가까운 높이가 자산 요약을 화면 밖으로 밀어내던 것이 결정적이었습니다.
- **바로가기 여섯 개는 한 묶음으로 접힙니다.** 앞 줄은 **기록하기**(문자등록·직접입력 — 기준월과 무관), 뒷 줄은 **보기**(한 장 리포트·소비분석·예산·AI 코치 — 고른 달을 따라감).
  → **`카드·계좌` 는 뺐습니다.** 하단 탭에 자리가 있어 한 번이면 닿습니다. 그 자리를 `한 장 리포트`(§12.14)가 받았습니다 — 소비분석 안에만 있어 찾지 못했다는 말을 들었습니다. 줄의 성격은 지킵니다: 리포트는 **보는** 것이므로 기록 줄이 아니라 뒷 줄로 갔고, 그래서 앞 줄이 둘·뒷 줄이 넷입니다(높이는 그대로입니다). **쪼개서 머리글을 하나 더 두지는 않습니다**: 버튼은 숫자를 말하지 않으므로 기준월과 모순될 수 없고(불편의 원인은 "8월이라고 적혀 있는데 숫자가 안 바뀐다"였습니다), 구역을 늘리면 스크롤을 줄이려는 노력과 부딪힙니다. 순서만으로 성격이 보입니다.
  → `직접입력`은 **오늘 날짜**로 시작합니다. 8월을 보다가 눌렀다고 8월로 채우면 사용자가 알아채지 못한 채 과거에 기록됩니다. 모두 다른 화면으로 가는 버튼이고 그 자체로는 정보가 없어서, 늘 펼쳐 두면 결산·예산 같은 실제 정보가 아래로 밀립니다. 마지막에 고른 상태를 `localStorage`(`smartmoney_home_shortcuts`)에 기억합니다 — 가계부 데이터가 아니라 화면 취향이고, 기기를 다시 열어도 그대로여야 뜻이 있습니다.
- **가용 한도는 `spareOf` 하나에서 옵니다.** 이 화면이 `수입 − 고정비 − 저축`을 손으로 다시 적고 있었습니다 — §11.4가 "한 곳에 두라"고 적어 둔 바로 그 식이고, 예산 화면에서 식이 바뀌면 이 화면만 옛 값을 말하게 됩니다.

### 12.9 내역 찾기와 CSV (`services/query.ts`)

화면마다 자기 필터를 갖고 있었습니다. 계좌 내역은 그 계좌만, 내역 목록은 **그 달 안에서만** 검색했습니다. 그래서 "작년에 그 병원 얼마 냈지"에 답할 자리가 없었습니다.

조건을 값(`LedgerQuery`)으로 다루면 세 가지가 한 함수로 해결됩니다 — **전체 기간 검색**, **비슷한 항목 모아 보기**, **카테고리별 내역 보기**.

- **유사 항목은 글자 그대로 비교하지 않습니다.** 명세서가 같은 곳을 `(주)`·지점·승인번호를 붙여 여러 모양으로 적으므로 `normaliseMerchant`(§10)로 견줍니다 — `스타벅스 강남지점`으로 찾으면 `스타벅스강남`도 나옵니다.
- **고정·변동 조건은 수입 건에 걸지 않습니다.** 지출의 구분이기 때문입니다(§9.6).
- 기간을 **한쪽만** 주면 그 달만 봅니다. 사용자가 한 칸만 채우는 일이 흔합니다.
- 들어가는 길: 내역 목록의 `전체 찾기`, 거래 수정의 `기간·범위를 정해 모아 보기`, 정기 결제 목록에서 한 항목 누르기.
- 목록은 **200건까지** 보여 주고 그 이상은 CSV 로 안내합니다. 수천 줄을 그려도 읽히지 않습니다.

**CSV 내보내기**(`toCsv`)는 조회 결과를 그대로 내려받습니다 — 조회한 것이 곧 내보낼 것입니다.

- **금액에 콤마를 넣지 않습니다.** 화면에서는 `1,234,000원`이지만 CSV 는 다시 계산에 쓰이는 파일이고, 콤마가 든 숫자는 엑셀에서 문자가 됩니다 — `parseInt("1,234,000")`이 1이던 것과 같은 함정입니다(§12.2).
- **앞에 BOM 을 붙입니다.** 엑셀은 BOM 이 없으면 UTF-8 한글을 깨진 상태로 엽니다 — 가져올 때 euc-kr 을 다루며 배운 문제를 반대 방향에서 만나는 셈입니다(§7.2).
- 콤마·따옴표·줄바꿈이 든 값은 감싸고 따옴표는 두 번으로 씁니다(계좌 이름에 콤마가 들어갑니다).

### 12.10 정기 결제 모아 보기

고정비 판정(§10)이 이미 반복을 찾아내는데 **모아 볼 자리가 없었습니다** — 고정비 화면의 한 줄 요약뿐이었습니다. 구독이 하나씩 늘어난 것을 알아차리는 일은 개인 가계부에서 값이 가장 큰 점검이고, 계산은 이미 다 되어 있었습니다(실제 기기에서 14건 · 매월 약 153만원).

- **최근 금액과 평균을 함께** 보여 줍니다. 구독료가 오르면 둘이 벌어지고, 그 차이가 곧 알아차려야 할 사실입니다(오른 항목은 붉게).
- **두 달 넘게 안 보이는 것은 표시만 하고 빼지 않습니다.** 해지됐거나, 이름이 바뀌었거나, 명세서를 아직 안 넣은 것입니다 — 셋 다 사용자가 알아야 할 사실이고 판단은 사람이 합니다(§17.1).
- 수입은 빠집니다. 급여가 `정기 결제` 목록에 오르면 그 목록의 뜻이 달라집니다.
- 한 항목을 누르면 그 가맹점의 내역을 기간·범위를 정해 모아 봅니다(§12.9).

### 12.11 첫 사용 안내

등록을 마치면 **빈 화면**이었습니다. 카드·계좌를 등록하고 명세서를 받아 가져오라는 흐름을 스스로 알아내야 했고, 빈 상태 문구는 화면마다 흩어져 있었습니다.

홈 맨 위에 네 걸음을 놓습니다 — `카드·계좌 등록` → `명세서 가져오기` → `고정비 가려내기` → `예산 정하기`. **순서가 곧 의존 관계**입니다: 계좌가 없으면 가져올 곳이 없고, 내역이 없으면 분류할 것이 없고, 분류가 안 되면 예산이 뜻을 갖지 못합니다.

- **끝났는지는 데이터가 말합니다**(`services/onboarding.ts`). 사용자가 체크하는 목록이 아니라 실제로 되어 있으면 끝난 것입니다 — 그래서 앱을 다시 깔아도, 백업을 복원해도 상태가 맞습니다.
- `고정비 가려내기`는 **고정비로 판정된 건이 하나라도 있는가**로 봅니다. 가져온 직후에는 전부 변동비 추정이고, AI 자동 분류나 사람의 손이 닿아야 고정비가 생깁니다(§10).
- **한도 0원은 "정하지 않음"입니다** — §11.5의 `UNSET` 과 같은 규칙.
- **다음에 할 하나만 강조합니다.** 넷을 동시에 권하면 아무것도 고르지 못합니다.
- **다 끝나면 사라집니다.** 끝난 목록이 홈에서 가장 값진 자리를 계속 차지할 이유가 없습니다.
- 결산 카드 **앞**에 둡니다 — 아직 결산할 것이 없을 때가 이 안내가 필요한 때입니다.

### 12.12 홈이 먼저 말해 주는 것 (`services/upkeep.ts`)

이 가계부의 가장 큰 약점은 계산이 아니라 **사람이 잊는 것**입니다. 명세서를 안 넣으면 그 달이 통째로 비고, 백업을 안 하면 기기 고장이 곧 전손이며(§1 — 서버가 없습니다), 구독료가 오른 것은 명세서를 한 줄씩 읽어야 알 수 있었습니다. **셋 다 앱이 이미 아는 사실입니다** — 마지막 결제월, 마지막 백업 시각, 반복 판정의 금액. 계산을 새로 하지 않고 있는 것을 말합니다.

홈 맨 위에 한 줄씩 놓고, 무게에 따라 색이 다릅니다 — 백업(붉음) → 명세서(주황) → 오른 금액(호박) → 예고(회색). **되돌릴 수 없는 것이 먼저**입니다. 전부 붉게 칠하면 무엇이 급한지 가려지지 않습니다.

**넷 다 "근거가 없으면 한 줄도 내지 않습니다"**(§17.1). 명세서를 한 번도 넣지 않은 카드, 반복으로 판정되지 않은 결제, 내역이 하나도 없는 가계부에는 할 말이 없습니다.

#### 이번 달 명세서 (`missingStatements`)

- 근거는 **"지난달은 들어왔는데 이번 달은 아직"**입니다. 이번 달 것만 보고 판단하면 해지한 카드와 오래 안 쓴 카드가 매달 올라오고, 그 목록은 곧 아무도 읽지 않게 됩니다. 지난달이 있었다는 것만이 "지금도 쓰는 카드"라는 근거입니다.
- **달이 시작하자마자 묻지 않습니다**(10일부터). 명세서는 결제월 초에 나옵니다 — KB는 9월 명세서를 9월 3일에 보내고 롯데는 중순입니다. 1일부터 "없습니다"라고 말하면 알림이 아니라 잡음입니다.
- 실제 자료(2026-09-23 기준)에서 다섯 장 중 **롯데·삼성 두 장**이 걸렸습니다. KB·우리·신한은 9월분이 들어와 있어 조용합니다.

#### 정기 결제 예고 (`upcomingCharges`)

- 반복 판정(§10)이 이미 결제일과 금액을 압니다. 남은 것은 **오늘로부터 며칠인가**뿐입니다.
- **이번 달에 이미 나간 것은 말하지 않습니다.** `lastSeen` 이 이번 달이면 그 결제는 끝난 것이고, 그런데도 "3일 뒤"라고 말하면 같은 돈이 두 번 나가는 것처럼 읽힙니다.
- 두 달 넘게 안 보이는 것(§12.10 `looksStopped`)도 뺍니다 — 끊겼을 수 있는 결제를 예고하는 것은 지어내는 일입니다.
- 31일 결제는 30일인 달에 **말일로 당깁니다.** 이달 결제일이 지났으면 다음 달을 봅니다.
- **가까운 셋까지**(`UPCOMING_LIMIT`). 실제 자료에서 이레 안의 정기 결제가 넷이었고, 백업·명세서까지 더하면 첫 화면이 알림으로 덮입니다. 예고는 이 목록에서 가장 가벼운 소식이고 전부 보는 자리는 이미 있습니다(§12.10).

#### 오른 금액 (`amountJumps`)

- **평균이 아니라 바로 앞 결제와 견줍니다**(`RecurringItem.previous`). 평균에는 방금 오른 금액이 이미 섞여 차이가 희석되고, 사용자가 확인할 수 있는 사실도 "지난달보다 올랐다" 쪽입니다.
- 문턱이 **둘**입니다 — 5% **그리고** 1,000원. 비율만 보면 1,000원짜리의 100원이 10%로 걸리고, 금액만 보면 50만원 월세의 1만원이 매달 올라옵니다.
- 45일이 지난 인상은 말하지 않습니다. 내린 것도 말하지 않습니다 — 알아차려야 할 사실이 아닙니다.
- **묶음 줄은 이미 같은 건수끼리 견줍니다.** 통장은 같은 날 여러 건을 한 줄로 묶고 **건수를 이름에 씁니다**(`터널/도로 3 건`). 그 건수가 반복 판정의 열쇠에도 들어가 `3 건` 은 다른 달의 `3 건` 과만 묶입니다. 실제 자료의 4,600원 → 6,000원이 그 경우이고 **1건당 1,533원 → 2,000원**, 진짜로 오른 것입니다. 다만 이름에 `3 건` 이 적혀 있어 "횟수가 늘어난 것 아닌가" 하고 읽히므로 **1건당 얼마였는지를 함께 적습니다**(`bundledCount`).
  → **숫자 앞에 공백이 있어야 건수로 봅니다.** `우체００２건`(실제 자료)은 우체국 계좌 번호이지 2건이 아닙니다 — 붙여 쓴 숫자를 건수로 읽으면 223,130원짜리 금융 거래가 `1건당 111,565원` 이라는 없는 사실이 됩니다(§17.1).
- **`카드대금` 은 뺍니다.** 그 값은 한 달 치 소비의 합이라 매달 달라지는 것이 정상이고, 실제 자료에서 `우리카드결제` 가 522,347원 → 814,623원으로 잡혔습니다. 그 숫자는 카드·계좌 화면과 청구예정액이 이미 더 정확히 말합니다(§9.4). 매달 뜨는 알림은 곧 읽히지 않습니다.

#### 씀씀이가 늘어난 카테고리 (`categorySurges`)

`무엇이 달라졌나`에 답하는 자리가 없었습니다. 예산 경고(§11.5)는 **한도를 정해 둔** 카테고리만, 그 한도에 견주어 말합니다 — 한도를 아직 정하지 않았다면 아무 말도 하지 않고, 정확히 그때가 무엇이 달라졌는지 알고 싶은 때입니다.

- **지난달 같은 기간과 견줍니다.** 이번 달은 진행 중이라 지난달 **전체**와 견주면 언제나 줄어든 것처럼 보입니다 — 23일에 한 달 치를 이길 수는 없습니다. 양쪽 다 1일부터 오늘 날짜까지로 자릅니다(§11.5의 `upTo` 와 같은 태도). 지난달에 없는 날이면 그 달 말일까지 봅니다(3월 31일에 2월을 보면 28일까지).
- **건수와 금액을 둘 다 봅니다.** 한 번 크게 지른 것은 그 거래를 보면 되고, 여기서 알아차려야 할 것은 **씀씀이가 늘어난 것**입니다. 건수가 늘고, 금액이 50% 이상 **그리고** 30,000원 이상 늘었을 때만 말합니다.
- **지난달에 없던 카테고리는 말하지 않습니다.** 견줄 것이 없으면 "늘었다"고 말할 수 없습니다(§17.1).
- `카드대금`·`저축`은 뺍니다 — 늘어도 소식이 아닙니다. 수입도 세지 않습니다.
- 홈에는 **둘까지**(`SURGE_LIMIT`). 전부 올리면 되돌릴 수 없는 알림이 밀립니다.
- 실제 자료로 확인: 8월 23일 기준 `쇼핑 404,971원 늘었습니다 · 8월 1~23일 14건 453,647원 · 지난달 같은 기간 2건 48,676원`.

#### 백업 리마인더 (`backupDue`)

- 간격은 **`설정 → 기타 설정 → 백업 알림 기간`**에서 정합니다. 기본 30일, `0`이면 알리지 않습니다 — 매일 백업하는 사람에게 30일은 늦고, 한 달에 한 번 여는 사람에게 7일은 잔소리입니다. 끄는 것도 사용자의 결정입니다(§17.2).
- **내역이 없으면 말하지 않습니다.** 지킬 것이 없는데 권하는 것은 잡음입니다.
- **한 번도 안 했으면 그렇게 말합니다.** "며칠 지났다"고 적을 수 없는 상태와 오래된 상태는 다른 사실입니다.
- **마지막 백업 시각은 localStorage 에 둡니다**(`smartmoney_last_backup`). DB 에 두지 않는 까닭: 백업 파일에는 자기 자신이 언제 만들어졌는지 적힐 수 없고, 그 파일을 다른 기기에서 복원하면 **저쪽 기기의 백업 시각**이 따라와 이 기기가 지켜지고 있다고 잘못 말하게 됩니다. 지켜야 할 것은 **이 기기의 IndexedDB** 이므로 기억도 이 기기에 둡니다.
- 적는 것은 **"백업을 내보냈다"까지**입니다. 브라우저가 내려받기를 가로챈 뒤의 일은 페이지에 보이지 않아, 파일이 실제로 저장됐는지는 알 수 없습니다(§17.1).

#### 닫기 — 그리고 백업만 다른 뜻

알림을 닫을 방법이 없으면 **이미 아는 사실이 매번 첫 화면을 차지합니다.** 알림이 읽히지 않게 되는 가장 흔한 경로가 이것이라, 줄마다 `X` 가 있고 **옆으로 밀어도** 닫힙니다.

- **닫은 기록은 예산 경고와 같은 자리에 담습니다**(`dismissedAlertIds` · `smart_money_dismissed_alerts_v1`). 저장소를 하나 더 만들면 "닫은 것"이 두 곳에 흩어지고 한쪽만 고쳐집니다. 예산 경고는 날짜 없이 id 만 적어 왔고, 그 줄은 여기서 **기한 없는 닫기**로 읽혀 지금과 똑같이 동작합니다.
- **셋은 닫기가 저절로 만료됩니다.** id 가 이미 사실을 담고 있어서입니다(`STATEMENT:카드:2026-09`) — 10월이 되면 id 가 바뀌어 9월에 닫은 기록이 비껴가고 다시 뜹니다. 예고와 인상도 같습니다.
- **백업만 닫기가 미루기입니다.** `BACKUP:never` 는 백업을 할 때까지 id 가 영영 그대로라, 영구 숨김을 허용하면 기기 고장이 곧 전손인 구조에서 **유일한 방어선이 실수로 민 손가락 하나에 꺼집니다**(§1). 그래서 닫을 때 날짜를 함께 적고(`BACKUP:never|2026-09-23`) **알림 기간만큼만** 쉬었다가 다시 올라옵니다. 영영 끄는 길은 `설정 → 기타 설정 → 알림 기간 0일`에 그대로 둡니다 — 끄는 것은 사용자의 결정이되(§17.2) 그 결정은 설정에서 명시적으로 하는 편이 맞습니다.
  → **날짜가 없거나 읽을 수 없는 백업 기록은 감추지 않습니다.** 언제 닫았는지 모르면 얼마나 미룰지도 알 수 없고, 모를 때 감추는 쪽으로 기울면 그 침묵이 곧 전손입니다(§17.1과 같은 태도).
- **닫은 것을 버리지 않습니다.** 잘못 닫았을 때 되돌릴 방법이 없으면 닫기가 위험한 버튼이 됩니다. 묶음 아래 `숨긴 N건 보기`로 펼쳐 흐리게 보여 주고 줄마다 `다시 보이기`가 붙습니다.
  → **새 창을 만들지 않았습니다.** 여기서 하려는 일은 거의 언제나 "다시 보이게"이고, 그 일에 화면을 옮겨 다닐 값이 없습니다 — z-층과 이동이 하나씩 늘 뿐입니다(§12.3과 같은 방식).
  → **다시 보이게 할 때는 그 알림의 기록을 전부 지웁니다**(`withoutDismissal`). 백업은 닫을 때마다 날짜가 달라 기록이 여러 줄로 쌓이고, 하나만 지우면 다른 줄이 계속 감춥니다.

#### 밀어서 닫기 (`services/swipe.ts`)

라이브러리를 더하지 않았습니다 — 손가락이 얼마나 움직였는지를 보는 산수이고, 이 앱은 쓰지 않는 의존성을 남기지 않기로 했습니다(§2에서 `motion` 을 걷어낸 것과 같은 까닭).

**위험한 것은 애니메이션이 아니라 판정입니다.** 알림 줄은 세로로 스크롤되는 목록 안에 있고, 그 자체가 **누르면 화면을 여는 버튼**입니다. 세 동작이 같은 손가락 하나를 두고 다툽니다.

| 하려던 것 | 잘못 판정하면 |
| --- | --- |
| 목록을 세로로 넘김 | 스크롤이 끊기고 알림이 따라 움직입니다 |
| 알림을 눌러 이동 | 손가락이 몇 px 흔들렸다고 닫힙니다 |
| 옆으로 밀어 닫기 | 아무 일도 일어나지 않습니다 |

- **축을 먼저 잠급니다**(`swipeAxis`). 8px 를 넘기 전에는 아무 방향도 아니고, 한 번 정해지면 그 방향만 봅니다. **비기면 세로**입니다 — 스크롤을 뺏는 쪽이 닫기를 놓치는 쪽보다 나쁩니다.
- 세로 넘기기는 브라우저에 맡깁니다(`touch-action: pan-y`). 우리가 가로만 가져갑니다.
- 닫히는 거리는 **줄 너비의 35%, 최대 72px**(`swipeDismisses`). 좁은 화면에서 고정 픽셀은 너무 길고 넓은 화면에서는 너무 짧습니다. 방향은 가리지 않습니다 — 왼쪽으로 미는 사람과 오른쪽으로 미는 사람이 모두 있고 둘 다 "치운다"는 같은 뜻입니다.
- 그 지점을 넘으면 **고무줄처럼 눌러** 덜 따라옵니다(`swipeOffset`). 끝까지 따라오면 어디서 손을 떼야 닫히는지 알 수 없습니다.
- **민 뒤에 따라오는 `click` 을 막습니다.** 밀어 놓고 화면이 열리면 안 됩니다.
- **`X` 는 늘 있습니다.** 미는 몸짓을 모르는 사람과 마우스를 쓰는 사람이 있으므로 스와이프는 거들 뿐입니다.
- 흐려지는 정도는 **너비를 읽지 않고** 고정 거리로 셈합니다 — 그리는 중에 `ref` 를 보면 첫 렌더에 값이 없고, 있어도 레이아웃을 강제로 다시 재게 합니다(eslint 의 `Cannot access refs during render` 가 이것을 잡았습니다).

**이 줄들은 기준월을 따르지 않습니다.** 전부 *지금* 기준의 사실이라 8월을 보고 있어도 그대로입니다 — 자산 요약(§12.7)과 같은 자리이고, 그래서 줄마다 자기 달을 이름으로 말합니다.

### 12.13 환불·취소 짝짓기 (`services/refunds.ts`)

환불은 두 줄로 남습니다 — 나간 줄과 돌아온 줄. 합계에서는 서로 상쇄되지만(§9.5) **목록에서는 따로 놓여** 그 달에 실제보다 많이 쓴 것처럼 보입니다. 짝을 지어 보여 주면 "이건 되돌아온 돈"이라는 사실을 한눈에 알 수 있습니다. 한 장 리포트(§12.14)가 이 결과를 씁니다.

**자동으로 지우거나 합치지 않습니다.** 두 줄 다 명세서에 실제로 있는 줄이고, 없애면 명세서와 가계부가 달라집니다(§17.3).

**무엇으로 짝을 짓는가는 실제 자료로 정했습니다.** 1,420건에 세 규칙을 차례로 걸었습니다.

| 규칙 | 결과 |
| --- | --- |
| 같은 계좌 · 같은 금액 · 반대 방향 | 후보 25건 이상, **거의 전부 오답** — `양은실` 출금과 `양승표` 입금이 70,000원으로 같다고 짝이 되었습니다. 남남인 이체입니다. |
| 위 + 가맹점 이름이 **정확히** 같을 것 | **0건.** 환불 줄은 이름이 그대로 오지 않습니다 — `서울페이` / `서울페이환불`. |
| 위 + 환불 쪽 이름이 결제 쪽 이름을 **품을 것** | **1건**, 그리고 그 1건이 진짜 환불이었습니다. |

- **포함에 방향이 있는 것이 핵심입니다.** 반대로 두면 `카뱅오픈양승현` 출금과 `양승현` 입금이 짝이 되어(200만원, 40일 뒤) 남의 이름이 든 이체가 환불로 둔갑합니다. 환불 줄은 결제 줄의 이름에 `환불`·`취소`가 **붙는** 모양이지 그 반대가 아닙니다.
- 이름을 견주기 전에 `환불`·`취소`·`반품`·`차감` 을 떼고 `normaliseMerchant`(§10)로 정규화합니다.
- **`이체`·`카드대금` 은 짝짓지 않습니다.** 이체는 옮긴 돈이라 애초에 지출로 세지 않고(§6.5) 나갔다 들어온 모양이 환불과 똑같아 거짓 짝이 가장 많이 나오는 자리입니다. 카드대금은 그 카드의 명세서가 따로 있습니다.
- 창은 **60일**입니다. 카드 환불은 보통 며칠이지만 명세서가 다음 달로 넘겨 청구하는 일이 흔합니다.
- **한 결제는 한 번만 쓰입니다.** 같은 곳에서 같은 금액을 두 번 쓰고 한 번 환불받았다면 짝은 하나여야 합니다 — 둘 다 짝지으면 되돌아온 돈이 두 배로 보입니다. 환불에 가장 가까운 결제를 고릅니다.
- **놓치는 것이 있습니다.** `(주)무신사` 로 청구하고 `무신사` 로 돌려주면 잡히지 않습니다. 그쪽이 맞습니다(§17.2) — 없는 짝을 만들어 그 달 지출을 줄여 보이는 것보다, 못 찾고 두 줄로 두는 편이 낫습니다.

### 12.14 한 장으로 보는 결산 (`services/reportCard.ts` · `ReportCardModal`)

가계부를 계속 쓰게 만드는 것은 결국 **돌아보는 재미**입니다. 그런데 숫자는 화면 여섯 곳에 흩어져 있었습니다 — 결산 카드, 고정비 화면, 소비분석 도넛, 예산의 실적, 연도별 비교. "8월이 어땠는가"에, "2026년 전체가 어땠는가"에 한 번에 답하는 자리가 없었습니다.

**달과 해가 한 함수·한 화면입니다.** 두 벌로 만들면 같은 산식이 두 벌이 되고 한쪽만 고쳐질 자리가 생깁니다 — 이 앱에서 세 번 겪은 일입니다(§9.5 · §11.7 · §12.7). 범위를 가리는 것은 `key` 하나뿐이고, 날짜가 `YYYY-MM-DD` 라 **앞자리 비교 하나로** 둘 다 걸러집니다(`2026-08` / `2026`).

담는 것: 수입·지출·남은 돈(건수 포함) · 앞 기간과의 차이 · 고정/변동/저축의 모양 · 가장 많이 쓴 곳 여섯 · (해를 볼 때) 달마다 얼마를 썼나와 가장 많은 달 · 그 기간에 돌아온 돈(§12.13).

- **정의를 새로 만들지 않습니다.** 고정비·변동비·저축은 `actuals.actualRows` 를 그대로 부릅니다(§11.4) — 여기서 직접 걸러 내면 `고정 + 변동 + 저축 = 총지출` 이 이 화면에서만 어긋나고, 어느 쪽이 맞는지 알 수 없게 됩니다. 실제 자료로 검산했습니다(2026-08 · 2026년 모두 오차 0).
- **넘기는 목록은 이미 걸러져 있어야 합니다** — 옮긴 돈은 세지 않습니다(`spendingTransactions`, §6.5).
- **앞 기간에 자료가 없으면 `null` 이고 그 블록을 그리지 않습니다.** 견줄 것이 없는데 `0원`이라고 쓰면 "같았다"는 거짓이 됩니다(§17.1). 수입이 0이면 남긴 비율도 `null` 입니다.
- 해를 볼 때 **내역이 없는 달도 0으로 남깁니다** — 빼면 "그 달에 쓰지 않았다"가 "그 달이 없었다"로 보입니다(§12.4와 같은 이유).
- **들어가는 자리는 소비분석 하나**이고, **보고 있는 모드를 그대로 이어받습니다** — 연도별 비교에서 누르면 그 해가, 월별에서 누르면 그 달이 열립니다. 기간을 고르는 자리가 이미 그 화면이고(§12.5), 다른 곳에 또 두면 어느 기간의 리포트인지 다시 정해야 합니다. `기간 추이`는 임의 구간이라 한 장으로 접히지 않으므로 그때는 달로 엽니다.

**견줄 기간을 고를 수 있습니다.** 기본은 바로 앞 기간(지난달·지난해)이지만, 8월처럼 해마다 성격이 다른 달은 **작년 같은 달**과 견주는 편이 뜻이 있습니다. 달은 연월 선택 창이(§12.6), 해는 자료에 있는 해를 칩으로 보여 줍니다.

- **모양이 다르면 무시하고 기본값으로 돌아갑니다.** 달을 보면서 해와 견주면 한쪽은 한 달, 다른 쪽은 열두 달이라 "지출이 늘었다"가 아무 뜻이 없습니다.
- **보는 기간이 바뀌면 견줄 기간도 기본값으로 되돌립니다.** 8월을 2025년 8월과 견주어 두고 `이 해`를 누르면 고른 값과 보는 것의 모양이 어긋납니다.
- **고른 기간에 내역이 없으면 그렇다고 말합니다** — 블록을 통째로 감추면 방금 고른 사람에게는 화면이 고장 난 것으로 보입니다. 판정은 그대로입니다(`before` 는 `null`, 지어내지 않습니다) — **무엇을 물었는지**(`compareKey`)를 따로 들고 있어 화면이 그 이름을 말할 수 있습니다.
- 기본값이 아닌 기간을 고르면 `기본값(바로 앞 기간)으로` 한 줄이 함께 나옵니다.

**이미지·PDF 저장은 인쇄로 합니다.** `html2canvas` 같은 것을 넣지 않았습니다 — 브라우저의 인쇄 대화상자에 `PDF로 저장`이 이미 있고 어느 기기에서나 같은 방식으로 동작합니다. 200KB짜리 의존성을 얹는 것과 맞바꿀 값이 아닙니다(§13.3과 같은 판단). 인쇄 규칙은 `index.css` 의 `@media print` 에 있고, 모달이 `<body>` 로 포털되므로(§14.4) **형제 노드를 감추는 것**으로 끝납니다. 끝나면 `printing-report` 표시를 반드시 뗍니다 — 남으면 다음 인쇄에서 엉뚱한 것이 감춰집니다. `afterprint` 를 주지 않는 브라우저가 있어 뒤늦게 한 번 더 치웁니다.

## 13. PWA와 배포

```jsonc
// wrangler.jsonc
{ "name": "smart-money", "compatibility_date": "2026-09-10",
  "assets": { "directory": "./dist", "not_found_handling": "single-page-application" } }
```

- Cloudflare: Build command `npm run build`, Deploy command `npx wrangler deploy`. 배포 디렉터리는 `wrangler.jsonc`의 `assets.directory`가 결정합니다.
- GitHub `main`에 푸시하면 Cloudflare가 빌드·배포합니다(1~3분).

### 13.1 무엇이 웹에 올라가는가

**배포되는 것은 `dist/` 뿐입니다.** `vite build`가 만들고, 그 안에 들어가는 것은 번들 결과물과 **`public/`을 그대로 복사한 것**뿐입니다(`publicDir`·`outDir`을 따로 설정하지 않아 기본값입니다). 저장소 루트의 다른 파일은 **서비스되지 않습니다.**

- **`public/`에 둔 것은 그대로 웹에 공개됩니다.** 이것이 이 절의 요점입니다 — 가계부 백업(`.db`·`.smbk`), 명세서 샘플, 메모 따위를 그 안에 두지 마세요. 주소만 알면 누구나 내려받습니다.
- `.gitignore`가 `*.db`·`*.sqlite`·`*.smbk`를 어디서든 걸러 주므로 **GitHub 경유 배포로는** 새지 않습니다. 다만 로컬에서 `npx wrangler deploy`를 직접 하면 git과 무관하게 **작업 폴더의 `public/`이 그대로 실립니다.** 무시 규칙이 이 경로를 막아 주지 않습니다.
- 실제로 저장소 루트 `DB Backup/`에 백업 `.db`가 커밋되어 공개 저장소에 올라간 일이 있었습니다. **웹으로는 서비스되지 않았습니다**(루트는 `dist/`에 복사되지 않으므로) — 한 번 겪어 두었으니, 같은 걱정이 생기면 `find dist -iname "*.db"`로 확인하면 됩니다.
- Cloudflare 빌드 컨테이너는 저장소를 clone하므로 빌드 시점에 그런 파일의 사본을 갖습니다. 일회성 환경이고 산출물에는 포함되지 않습니다.
- `workbox.globPatterns`에 **`wasm`을 반드시 포함**해야 오프라인에서 DB가 열립니다.
- 서비스 워커는 HTTPS 또는 localhost에서만 동작합니다.
- `registerType: 'autoUpdate'`라 **한 번 실행에서 새 버전을 받고 다음 실행에서 화면에 반영**됩니다. 사용자에게는 "두 번 열어보라"고 안내하거나, 새로고침 안내를 띄우세요.
- `ErrorBoundary`가 흰 화면 대신 오류 메시지와 `캐시 비우고 다시 열기`(서비스 워커·캐시 삭제 후 새로고침)를 보여줍니다.

### 13.2 앱 설치 안내는 한 기능입니다

설치를 권하는 자리가 셋입니다 — 홈 화면 맨 위의 배너, 설정 메뉴, 그리고 그 둘이 여는 **같은 안내 창**(`PWAInstallGuideModal`).

- **이름을 `INSTALL_FEATURE_NAME` 한 곳에 둡니다.** 예전에는 자리마다 달랐습니다 — `브라우저 없이 앱으로 설치` / `스마트폰에 '스마트 머니' 전용앱 설치` / `휴대폰에 '스마트 머니' 앱 설치하기`. **사용자가 같은 기능인지 물어볼 정도였습니다.** `휴대폰`·`스마트폰`도 섞여 있었고 `스마트폰` 하나로 씁니다.
  → 예외는 **브라우저 메뉴에 적힌 말**입니다(`[홈 화면에 추가]`, `[앱 설치]`). 그것은 우리 이름이 아니라 크롬·삼성 인터넷이 쓰는 말이므로 그대로 두어야 사용자가 찾을 수 있습니다.
- **배너는 자기 안내를 갖지 않습니다.** 예전에는 기종별 안내 팝업을 따로 들고 있어 같은 내용이 두 군데 있었고(한쪽만 고쳐질 자리), 삼성 인터넷 안내는 그쪽에만 있었습니다. 팝업을 없애고 그 내용을 설치 창으로 **옮겼습니다** — 지우지 않았습니다.
- **`X` 로 닫으면 이번 로그인 동안 다시 뜨지 않습니다**(`FinanceContext.installBannerHidden`). 배너는 `HomeView` 안에 있어 탭을 옮기면 언마운트되는데, 닫힘 상태를 그 안에 두었더니 **다른 탭에 다녀오기만 해도 다시 나타났습니다.** 닫는다는 것은 "지금은 됐다"는 뜻이고, 그 뜻이 화면 하나의 수명보다 길어야 합니다.
  → **저장하지 않습니다.** 세션(`currentUserId`)은 메모리에만 있어 새로 열면 로그인부터 다시 하므로, 이 상태도 그때 함께 사라지는 것이 "다음 로그인까지"와 정확히 같습니다. 사용자가 바뀌면 다시 보여 줍니다.
  → 영구히 감춰도 잃는 것이 없습니다 — 설치는 **설정 메뉴에 언제나** 있습니다.

### 13.3 초기 로드에 무엇이 들어가는가

**필요할 때 내려받습니다.** 주 청크가 한때 1,832KB(gzip 466KB)였고, 그 안에 **AI 키가 없는 사용자에게는 쓸모없는** SDK 두 개가 들어 있었습니다.

| 청크 | 크기(gzip) | 언제 |
| --- | --- | --- |
| 주 청크 | 793KB (220KB) | 처음 |
| `sql-wasm` | 658KB (323KB) | DB 열 때 |
| `xlsx` | 500KB (163KB) | 명세서 읽을 때 |
| `AnalyticsDashboardView`(recharts) | 469KB (132KB) | 소비분석 탭 |
| `CsvImportModal` | 43KB (12KB) | 가져오기 창을 **열 때** |
| `ReportCardModal` | 14KB (5KB) | 한 장 리포트를 **열 때** (홈·소비분석이 같은 청크) |
| `ConnectedAssetsView` | 36KB (10KB) | 카드·계좌 탭 |
| `@google/genai` | 388KB (69KB) | 제미나이 호출 |
| `@anthropic-ai/sdk` | 193KB (50KB) | 클로드 호출 |
| `qrcode` | 26KB (10KB) | 설치 안내 열 때 |

- **AI SDK 는 `import type` 으로 타입만 가져오고, 호출 순간에 `await import()`** 합니다. 정적 import 였을 때는 키가 없어도 전부 받았습니다.
- **차트 화면은 `React.lazy`** 입니다. `recharts` 는 소비분석 탭에서만 씁니다.
- **탭과 무거운 창도 나눕니다.** 카드·계좌 탭(`ConnectedAssetsView`)과 가져오기 창(`CsvImportModal`)은 홈만 보는 날에는 한 번도 그려지지 않습니다. 창을 나눌 때는 **열렸을 때만 그려야** 합니다 — 늘 마운트돼 있으면 `React.lazy` 가 뜻이 없습니다(§14.7).
- 새 무거운 의존성을 넣을 때는 **"처음 화면에 필요한가"**를 먼저 물으세요. 대개 아닙니다.
